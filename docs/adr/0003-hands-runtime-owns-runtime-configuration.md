# Hands Runtime owns runtime configuration

The Windows Tray Launcher owns settings UX but not the runtime configuration format. `hands.exe` remains the Config Authority for the runtime key, Tunnel ID, and tunnel profile, exposed to the launcher through a narrow machine-readable seam that keeps secrets out of process arguments; Phase 1 uses JSON over stdin for apply. `hands.exe` validates the full settings transaction and persists the canonical credentials plus the Windows command-based tunnel profile before reporting success, and only then may the launcher restart its owned runtime tree. This avoids a second credential/config implementation in C#, prevents half-applied settings, and lets the runtime evolve its platform-specific profile format without coupling it to the tray shell.

For launcher-managed configuration and runtime children, canonical persisted settings are authoritative: the launcher removes inherited `CONTROL_PLANE_API_KEY` and `CONTROL_PLANE_TUNNEL_ID` from each child environment, and the tunnel reads credentials from the canonical profile/secret references. Profile selection, the MCP executable, and the health endpoint are explicit launcher-owned inputs; inherited overrides cannot redirect them, while unrelated environment such as PATH, SystemRoot, temporary-directory settings, and supported proxy settings remains available. The parent environment and the existing standalone CLI/macOS/Linux precedence remain unchanged, so a successful Settings save has one predictable meaning for the launcher without changing legacy workflows.

The same configuration interface supports preparation without resubmitting credentials: the selected Hands Runtime validates stored settings and idempotently rebinds the Windows command profile to its own canonical executable path, returning a sanitized result and the canonical profile path for the launcher to use explicitly. Preparation failures preserve the previously committed configuration and prevent a stale-profile start; compatible release/rollback pairs retain a readable configuration format, and an incompatible format must fail without rewriting it. Relocation, release selection, and credential apply therefore share one Config Authority instead of teaching the C# launcher the profile format.
